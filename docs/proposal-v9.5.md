# 木木遊戲 — 上市級成熟度躍升方案（v9.5 · 目標 9.0+）

> **本文件是提案，不是執行清單。**
> 目的：把「上市商業成熟度 4.2 分」推到 **9.0 分以上**，並讓成品具備大公司水準。
>
> **前提共識**：可以接受長時間開發。因此本方案**不做取悅式取捨**，
> 每個缺口都做到「若這是一間上市公司的產品，它必須有的樣子」為止。
>
> **本方案取代 `task.md` 的 v9 內容**（v9 只解決了「能玩」，未涵蓋「能收錢、能量到數據、能上市」）。
> 執行時以本文件的階段劃分為準，`task.md` 保留為 Step 層的細節來源。

## 貳 — 目標定義：什麼叫「9 分成熟度」

> **9 分不是「功能多」，是「沒有任何一個環節會讓公司尷尬」。**

### 9 分必備條件（缺一項即扣到 8 分以下）

| # | 條件 | 驗證方式 |
| --- | --- | --- |
| **M1** | **40/40 關可在無錯誤下完成** | 自動行為測試逐關跑完 |
| **M2** | **真實金流可走通**：購買 → 憑證驗證 → 權益生效 → 復原訂閱 | 沙盒環境端到端測試 |
| **M3** | **Kids Category 家長確認流程**（Apple/Google 強制要求） | 商店送審前 100% 覆蓋 |
| **M4** | **遙測可外送 + crash reporting + Web Vitals 量測** | 後端收到事件 + crash 儀表板 |
| **M5** | **離線冷啟動 100% 成功**（飛航模式 × 10） | 自動驗證 + 實機 |
| **M6** | **首次啟動有可操作的同意流程**（COPPA／GDPR-K） | 玩家必須主動點選才進入 |
| **M7** | **CI 全綠才能合併**（typecheck／lint／content／assets／playable／a11y） | PR 必過 |
| **M8** | **關鍵指標全部有量測路徑**（不再是「待實測」＝架構上不可能） | 儀表板可查 |
| **M9** | **可及性達 WCAG 2.2 AA**（鍵盤全通、螢幕閱讀器可讀、對比達標） | 自動掃描 + 人工複核 |
| **M10** | **資安基線到位**（CSP、無 XSS 注入點、隱私資料不外洩） | 掃描 + 人工審查 |
| **M11** | **A/B 測試可執行**（定價、付費牆文案、教學流程） | 實驗框架可分配、可讀取 |
| **M12** | **帳號與家庭方案成立**（最多 3 個孩子檔案 + 進度同步） | 跨裝置同步可驗 |
| **M13** | **營運手冊齊備**（changelog、版本策略、客服流程、崩潰分級） | 文件存在且可執行 |
| **M14** | **成效研究可執行**（assessment UI 接線，30 戶流程可執行） | 實測完成 |

### 9 分**不**代表（避免走偏）

- 不需要 100 關、8 種玩法、10 種語系
- 不需要競品同等的內容量
- 不需要 native app（Web/PWA 可上市）
- 不需要後端團隊規模（可用 BaaS + serverless）

### 關鍵排序原則

1. **W0 先行** — v8 的教訓：沒有行為守門，所有後續工作都在裸奔
2. **W1 → W2 有序** — 先能玩，再好玩（否則是給不能玩的東西加特效）

4. **W4 是 W3 的前提** — 沒有後端，金流無法驗證、指標無法量測
5. **W6 最後** — 沒有前面六條線，上市準備是自欺欺人

## W0 — 地基：可玩性守門與迴歸防護

> **這是全部工作的前提。** v8 的 34 條守門全 PASS，但遊戲有 9 關永遠卡死。
> 根因是守門驗「檔案裡有這些字串」，不是「遊戲能玩」。

### W0.1 建立 jsdom 可玩性測試骨架

**為什麼**：目前 0 條行為測試。所有「這個功能能不能用」的問題都要靠人肉點。

**產出**：
- `tools/test-harness.mjs` — 可啟動完整遊戲環境的測試骨架
  - stub：`AudioContext`／`OfflineAudioContext`／`speechSynthesis`／`matchMedia`／`rAF`／`canvas 2D`／`Image.onload`／`localStorage`／`fetch`（攔截本地檔）
  - fake timers（避免不穩定的真實等待）
  - 透過 **DOM 與公開事件**操作，模擬真實玩家（不 import 私有狀態）
- `tools/verify-playable.mjs` — 可玩性守門，**先證明抓得到既有缺陷**
- `package.json` 新增 `test:play` script（`jsdom` 為唯一新 devDependency）

**守門檢查項（Step 109 詳解，摘要）**：

| id | 門檻 |
| --- | --- |
| `play-boot` | 遊戲可啟動，無未捕捉錯誤 |
| `play-start` | 點擊開始後遮罩消失、遊戲容器可見 |
| `play-tutorial` | 教學可完整走完並進角色選擇 |
| `play-character` / `play-levelmap` | 角色選擇、地圖可操作 |
| `play-level-enter` | 進關卡後有可互動選項 |
| `play-level-complete` | 關卡 1 可完成 3 回合並觸算 |
| `play-all-verbs` | 六種玩法各可推進 |
| `play-no-blocking` | 全流程無未捕捉錯誤、無 console.error |

**驗收**：`npm run test:play` 在修復前 **至少 3 條 FAIL**（證明守門有效）。

### W0.2 引擎契約重構（根治 9 關卡死）

**為什麼**：目前 4 種玩法有 3 種不同的「完成模型」，`session.js` 對每種都要特判 → 這是 F1/F2/F3 的**共同根因**。不先修，每加一個玩法就重蹈覆轍。

**產出**：
- `src/js/core/verb-contract.js` — 統一契約，宣告 4 種 `kind`：

| kind | 玩法 | 作答入口 |
| --- | --- | --- |
| `choice` | minimal-pair／rhythm／interference | `submit(id)` 一次判定 |
| `sequence` | sequence／memory-dual | `submit(id)` 逐項推進 |
| `place` | puzzle-assembly | `submit({pieceIndex,targetIndex})` |
| `match` | memory-match | `submit({slot})` 翻牌配對 |

  契約必備：`kind` / `build()`（**一律 async**）/ `getPrompt()` / `getOptions()` / `getCards()` / `getPieces()` / `submit(input, meta)` / `isComplete()` / `getFeedback()` / `playPrompt()` / `demonstrate()` / `replay()`
- 三個引擎改造為遵守契約（**保留舊方法作相容層**，既有呼叫點不爆）
- `session.js` 改為**零玩法特判**（守門會 grep 阻擋 `verb === "..."`）

**驗收**：
- `session.js` 中 `grep 'verb === "'` → **零結果**
- `session.js` 中 `__memory_done__` → **零結果**（移除魔法字串特例）
- `play-level-complete` 與 `play-all-verbs` 轉 PASS

### W0.3 全關卡覆蓋守門

**產出**：`play-verbs-coverage` — **40 關每一關**都能在無錯誤下走完 3 回合並觸發結算。依各玩法真實的正確作答路徑操作（不得直接改 `state` 跳過流程）。

**這是「推進不了劇情」的最終防線。**

## W1 — 可玩性與可及性（讓孩子真的能玩、看得懂）

### W1.1 入口與導航（消除所有卡死點）

| 缺陷 | 現況 | 修復 |
| --- | --- | --- |
| F4 教學卡在第 1 步 | 「播放聲音」按鈕 dispatch 無人監聽的事件 | 每一步都有真實前進路徑；移除 `tutorial.next` 包裝 |
| F6 序章信件無關閉鈕 | 靠 `setTimeout(2600)` 推進 | 改用 `story.js` 的可關閉信件面板；`speak()` 加 `onEnd` 回呼，**不用定時器猜長度** |
| F7 `startGame` 執行兩次 | `showStart()` 與 `wire()` 各綁一次 | 綁定只留一處 + `started` 旗標防禦 |
| F8 圖鑑無關閉鈕 | 點進去就出不來 | `overlayStack` 管理返回路徑，每層都有返回 |

**原則**：**所有流程推進由使用者行為或語音結束事件觸發，禁用定時器推進。**

### W1.2 角色尺寸與版面根治

**現況**：`renderCharacter()` 產出 `.char__art`，但尺寸規則寫給已被覆蓋的 `#character-img` → 角色以 **512px 原始尺寸**渲染，在 375px 寬的手機上溢出畫面、蓋住氣泡。

**修復**：
- `.char__art` 補齊尺寸契約（`max-height: var(--char-max-h, 34dvh)`）
- 移除失效的 `#character-img` 規則（同步更新 `responsive.css`）
- `#santa-container` 改為底部留白 + 明確 gap，氣泡加 `max-width` 防撐破
- `renderCharacter()` 改 `classList` 增量操作，不再覆寫 `className`（否則 mood 會遺失）

### W1.3 一眼看懂的介面

- 回合提示**視覺化**（自繪 SVG 圖示，非 emoji）
- 可互動元素 **≥ 48×48 CSS px**（觸控目標）
- 文字對比 ≥ 4.5:1（主要）、≥ 5:1（回合提示）
- 狀態提示用**動作詞**（「聽」「換你」）取代狀態詞
- 序列／記憶／拼合的**進行中視覺引導**（已答對項點亮、配對卡翻正、拼合片吸附）

### W1.4 可及性達 WCAG 2.2 AA

| 項目 | 現況 | 目標 |
| --- | --- | --- |
| 鍵盤操作 | 僅 4 處 `keydown` | 全流程可純鍵盤完成 |
| 螢幕閱讀器 | 15 處 aria/role | 關鍵流程全有 live region 與語意標籤 |
| 自動掃描 | 無 | 引入 axe-core 自動掃描，0 critical |
| 對比 | 未驗 | 程式化檢查全數達標 |
| 動效 | 已支援 reduced-motion | 擴大到所有動畫 |

### W1.5 觸控與裝置適配

- 觸控裝置的視差（`touchmove` + `passive`）
- 裝置方向變化的過場（已有 orientation overlay，需接完整流程）
- 各種螢幕尺寸的角色與選項排列

**W1 驗收**：`npm run test:play` 全綠 + `play-nav-complete`（完整導航無死路）+ `play-touch-targets` + axe 0 critical。

## W2 — 戲劇性與演出層（讓畫面跟人物對得上劇情）

> **這是 v8 最大的資源錯置**：素材做到了 9 分，但**沒有任何一層**把素材組成「舞台」。
> 結果是孩子看到雪地裡的暴龍，聽到深海的故事。

### W2.1 演出層（素材 → 機器）

**新增 `content/performances.json`** — 每個場景一份「舞台指示」：

```json
{
  "ice-age-christmas": {
    "id": "ice-age-christmas",
    "title": { "zh-TW": "冰河紀的聖誕", "en-US": "Ice Age Christmas" },
    "cast": [
      {
        "id": "dino-tyrannosaurus",
        "role": { "zh-TW": "雪原上的守護者", "en-US": "the Guardian of the Snowfield" },
        "entrance": "left",
        "props": ["lantern"]
      }
    ],
    "ambience": "snow-wind",
    "backdrop": "frozen-village"
  }
}
```

**新增 `src/js/core/performance.js`** — `castFor` / `entranceOrder` / `directiveFor` / `lineFor` / `applySceneCast`

**關鍵設計**：
- 場景卡司渲染到 `data-layer="character"` 層（**目前是空的**）
- `lineFor()` 讀既有 `dinoLines`（24 隻的專屬對白），**依場景與角色產生穩定挑選，不可用 `Math.random()`**
- 主角／搭檔與場景卡司**分開渲染**（不同層級）

**成果**：24 隻恐龍的專屬對白**第一次真正出現在遊戲裡**。

### W2.2 場景可辨識度（不只是換色）

**現況**：六個場景只有色票不同，`data-layer="character"` 層是空的 → 玩家感受不到切換。

**修復**：
- 每個場景在 `ridge` / `midground` 有**獨立的 clip-path 剪影**與漸層角度
- `data-layer="character"` 層放入**場景代表性剪影**（聖誕樹、蕨葉、冰稜…）
- `content/scenes.json` 的 `weather` 欄位**必須被消費**（不得留死欄位）
- 純 CSS 實作（維持離線體積）

### W2.3 劇情連貫

| 缺陷 | 現況 | 修復 |
| --- | --- | --- |
| C2 六章信件從未出現 | v8 寫的 263–330 字信件玩家一封看不到 | 每章首次進關卡先播過場（信件 + 搭檔立繪 + CTA） |
| C3 角色不跟章節走 | 永遠畫玩家選的那一隻 | 每關 `companion` 欄位，搭檔跟著章節走 |
| C4 24 隻圖鑑不在遊戲中 | 解鎖只給一行 toast | **隊伍列**（`#team-dock`）：已解鎖彩色、未解鎖剪影；新解鎖的恐龍**走出來**慶祝 |

**關鍵**：收集欲的回饋必須**看得見**，不是一行文字。

### W2.4 回合回饋三重奏

每次作答都要有 **聲音＋角色表情＋動態**：

- 答對 → `happy` mood + 角色 `celebrate` 音效 + 粒子 + 按鈕彈跳
- 答錯 → `hint` mood（**友善**，不是 `sad`）+ 柔和高音 + 搖頭
- **序列中間步** → 該項點亮 + 小反應（**不得**顯示答錯、不得扣分）

**原則**：幼兒產品，**錯了不懲罰**。

**W2 驗收**：`play-story-per-chapter`（六章各有一關通過過場＋卡司＋搭檔檢查）+ `play-team-visible` + `play-dino-lines`（專屬對白有被使用）。

## W3 — 商業管道與合規（讓公司真的收到錢）

> **這是 4.2 分的最大缺口，也是上市必被擋的地方。**

### W3.1 真實金流（取代「敬請期待」）

**現況**：購買按鈕最終只做 `track("purchase")` + 顯示「已記錄您的訂閱意向，敬請期待。」

**必須實作**：

| 項目 | 說明 |
| --- | --- |
| **商店 SDK 整合** | iOS：StoreKit 2；Android：Google Play Billing；Web：Stripe |
| **訂閱復原（Restore）** | **上架必檢**。App Store 審核會直接退件。目前完全沒有 |
| **憑證驗證** | 後端驗證 Apple/Google 憑證，簽發權益 token |
| **交易狀態機** | `pending` → `active` / `failed` / `cancelled` / `refunded`；**恢復購買**後需重發權益 |
| **降級／退款** | 退款後權益回收、到期前 30 天提醒 |
| **離線優惠券** | 兒童 App 常見（家長在 App Store 設定領取） |
| **權益來源統一** | `entitlements.js` 改為**以伺服器簽發的 token 為準**，不再讀 localStorage 的 `"premium"` 字串 |

**同時修正文案債**：

## W4 — 後端與觀測（讓一切可量測）

> **現況**：`telemetry.js` 第 57 行 `void 0;` — 事件永遠不會離開瀏覽器。
> 這代表所有「待實測」指標 **在架構上就無法量測**。它們不是「還沒測」，是「永遠測不了」。

### W4.1 遙測外送

**架構**：
```
事件 → 同意檢查 → sanitize → 本地佇列(離線緩衝) → Beacon/fetch 批次外送 → 後端 → 資料倉 → 儀表板
```

**要點**：
- 離線時事件**進佇列**，恢復網路後補送（不丟資料）
- `sendBeacon` 避免頁面關閉時丟失
- 事件字典（`content/telemetry.json`）**擴充**：目前缺關鍵事件

**必須補的事件**：

| 事件 | 為什麼需要 |
| --- | --- |
| `first_interaction` | **首次互動時間**（目標 ≤ 15 秒）—— 公測關鍵指標 |
| `level_start` / `level_complete` / `level_fail` | 卡死分析、逐關流失率 |
| `tutorial_step` / `tutorial_complete` / `tutorial_skip` | 教學流失點 |
| `hint_shown` / `hint_used` | 難度校準 |
| `scene_entered` | 場景轉換觀感 |
| `paywall_view` / `paywall_cta` / `purchase_attempt` / `purchase_success` / `purchase_fail` / `restore_started` | 漏斗 |
| `dex_unlock` / `team_viewed` | 收集迴圈 |
| `share_click` / `share_completed` | 病毒迴圈 |
| `session_end` | session 長度分布 |
| `crash` / `unhandled_rejection` | 穩定性 |

### W4.2 後端與帳號

**技術選型原則**：不建後端團隊，用 **BaaS / serverless**（Supabase / Firebase / Cloudflare Workers）。

**需要的後端能力**：

| 能力 | 說明 | 對應承諾 |
| --- | --- | --- |
| 匿名 → 帳號提升 | 首次啟動建匿名 ID，家長可綁定 | 跨裝置 |
| **孩子檔案（最多 3）** | 每個孩子獨立進度與設定 | 家庭方案「最多 3 個孩子帳號」 |
| **進度同步** | 家長登入後跨裝置同步 | 付費牆「跨裝置同步」 |
| 訂閱狀態查詢 | 權益以伺服器簽發 token 為準 | 金流 |
| 憑證驗證端點 | Apple/Google 憑證驗證 | 金流 |
| 遙測接收端點 | 批次接收 + 入倉 | 量測 |
| 推薦碼歸因 | 安裝歸因 | K-factor |
| 資料刪除請求 | 法規要求 | 合規 |
| 遠端設定 | 價格、開關、文案 | 營運 |

### W4.3 Crash reporting 與 Web Vitals

- **Crash 報告**：未捕捉例外、`unhandledrejection`、錯誤邊界 → 後端 → 依嚴重度分級
- **Web Vitals**：`LCP` / `CLS` / `INP` 量測（用 `PerformanceObserver`）→ 直接對應 v8 標記「待實測」的「≥ 55 FPS」
- **錯誤儀表板**：依版本 / 關卡 / 裝置分佈 → **知道孩子在哪一關崩潰**

### W4.4 A/B 測試框架

**現況**：`recordIntent()` 的註解寫「供定價 A/B 使用」，但**沒有任何 A/B 機制**。

**需要**：
- 實驗定義（`content/experiments.json`）
- 分流（依匿名 ID 雜湊，**穩定且可復現**）
- 曝光 / 轉換事件
- 結果查詢（透過 W4.2 後端）
- 首個實驗建議：**定價**（NT$790 vs 990）、**付費牆文案**、**教學流程長度**

**W4 驗收**：後端儀表板能查到 D7 留存、轉付費、分享率、K-factor、首次互動時間、逐關流失率；crash 儀表板非空；A/B 能分配並讀取結果。

**W5 驗收**：CI 全綠才能合併 + 覆蓋率報告 + 依賴掃描 0 critical + CSP 生效。
