# Step 110–112 — 統一引擎契約與回合 UI

日期：2026-11-20

## Step 110 — 統一引擎契約

**新增** `src/js/core/verb-contract.js`：
- `VERB_KINDS = ["choice", "sequence", "place", "match"]`
- `verifyEngineContract(engine)` — 供守門使用，檢查 `kind`／`build()` 為 async／
  `submit()`／`isComplete()`／`getFeedback()`／`playPrompt()`／`demonstrate()`／`replay()`

**改造三個引擎**：

| 引擎 | kind | 說明 |
| --- | --- | --- |
| `auditory.js`（sequence） | `sequence` | `submit()` 內部維護 `progressIndex` |
| `auditory.js`（minimal-pair / interference / rhythm） | `choice` | 比對 `answerId` |
| `puzzle.js`（assembly） | `place` | `submit({ pieceIndex, targetIndex })` |
| `puzzle.js`（pattern） | `choice` | 比對 `answerId` |
| `memory.js`（match） | `match` | `submit({ slot })` 包裝既有 `flip()` |
| `memory.js`（dual） | `sequence` | 依 `sequence` 順序逐項比對 |

**相容層**：舊的 `check()`／`getOptions()`／`getCards()`／`getSequence()`／`advance()` 全部保留，
`check()` 內部改為委派 `submit()`。

**順帶修正的既有缺陷**（見下方「守門揭露的缺陷」）：
- `puzzle.js` 原本沒有 `playPrompt()` → 契約補齊
- `auditory.js` 的節奏題用 `Math.random()` 決定題目，且選項 `rhythms.slice(0, 4)`
  **不保證包含正解**（正解可能落在第 5 個之後）→ 改為回合序號輪替，
  且選項以正解為中心取 4 個不同拍數。契約明訂「引擎不得使用 `Math.random()` 決定答案或題目」。

## Step 111 — session 改用統一契約

`src/js/core/session.js`：
1. `nextRound()` 改為 **async** 並 `await verbEngine.build()`（修掉 F3）
2. `answer(input)` 統一走 `submit()`，並依 `status` 分派：
   - `"wrong"` → 答錯 → `advanceHint()`（**錯誤時永不扣分**保留）
   - `"correct"`／`"progress"` → 作答有效；`result.correct` 才加分；`result.done` 才推進回合
3. **移除** `"__memory_done__"` 魔法字串分支
4. `session.start()` 的 `nextRound()` 加 `.catch()` → `handleFatal()`（絕不卡死在 loading）
5. 新增 `session.getFeedback()` 委派到引擎
6. `answer()` **回傳**作答結果（供 UI 決定回饋）

**session 內已無任何 `verb === "..."` 玩法特判，亦未 import `src/js/verbs/*`。**

## Step 112 — 回合 UI 支援四種玩法

`src/js/main.js`：
1. `renderRound()` 依 **`engine.kind`** 分派（不得以玩法名稱分派）：
   - `"choice"` → 按鈕網格
   - `"sequence"` → 按鈕網格 ＋ **序列進度指示**（`.seq-dot`，只顯示已答對幾項，**不洩漏答案順序**）
   - `"place"` → **拼合盤**（上方目標區／下方素材區）
   - `"match"` → 翻牌網格
2. **拼合盤 UI**：
   - 點素材切片 → 選取（`.is-selected`）；點目標格 → 放置
   - 呼叫 `session.answer({ pieceIndex, targetIndex })`（**由 session 統一走契約**）
   - 正確 → 吸附進目標區（`.is-filled`）＋ `burst()` 粒子 ＋ `chime.bell`
   - 錯誤 → 素材彈回（`.is-wrong` 動畫）＋ `ui.soft-low`
   - 使用既有 `<img>` ＋ dataUrl 切片路線（**未用 canvas 手繪**）
3. `renderMemoryBoard()` 改為呼叫 `session.answer({ slot })`，
   但**翻牌的視覺即時性保留**（`is-flipped` 在 submit 回傳前就加上）
4. `round:wrong` 的 `animate("#character-img", "shake")` 改為 `animate(".char__art", "shake")`
5. 新增 `round:progress` 事件監聽（序列／拼合的進行中回饋）

**新增 CSS**（`src/styles/components.css`）：`.seq-progress`／`.seq-dot`／
`.puzzle-board`／`.puzzle-target`／`.puzzle-slot`／`.puzzle-tray`／`.puzzle-piece`／
`@keyframes puzzle-bounce`

## 守門揭露的既有缺陷（已於本 Phase 修復）

| 缺陷 | 修復 |
| --- | --- |
| **`isLevelLocked()` 硬編碼 `levelId >= 8`** —— 關卡 8 以上**永遠鎖住**，<br>`progress.unlockedLevels` 寫了卻從沒被讀取 → 玩家推進不了劇情 | 改為以 `progress.unlockedLevels` 為準（`src/js/ui/levelmap.js`） |
| **節奏題正解不在選項內**（`rhythms.slice(0,4)` 與 `Math.random()` 抽題） | 選項以正解為中心輪替 |
| **puzzle／memory 的 UI 直接呼叫引擎，繞過 session** —— 回合永不結算 | 改由 `session.answer()` 統一派送 |
| **`memory` 翻錯會被當成答錯**（扣提示） | `submit()` 以 `status: "progress"` 回傳，翻錯只是配對過程的一部分 |

> 註：`isLevelLocked` 的修正屬 Step 113「40 關全部可完成」的必要前提
> （`isLevelLocked` 不讀進度，則第 8 關起永遠無法進入，`play-verbs-coverage` 必然失敗）。
> 修正僅改動鎖定判斷的依據，不改變任何關卡內容。
